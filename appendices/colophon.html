D.2 How it looks

The site theme is bootswatch litera with a layer of project SCSS on top. litera was picked because it is one of the few bundled themes that does not fetch a web font from Google’s servers, so the book renders identically offline and on a network that blocks Google. Appendix C says more about why that mattered.

Figures use a five-colour palette, defined in R/nus_theme.R and applied through theme_set() so no chapter has to remember it:

nus_colours
#>      blue   crimson      teal    orange      grey       ink     muted      rule 
#> "#003D7C" "#96233F" "#007E96" "#E8720C" "#BFC6CE" "#1F2933" "#5A6672" "#DDE3EA"

The first five are the series colours. ink, muted and rule are for text and gridlines.

The palette was tested in code. scripts/check_palette.R simulates protanopia, deuteranopia and tritanopia (Machado et al. 2009, full severity) and scores every pair by CIEDE2000, where the worst case is dE00 18.9, between blue and teal under deuteranopia. It checks that adjacent colours sit at least 8 L* apart, so the series survive a photocopy. And it checks thin-line contrast against white under WCAG 1.4.11: the first four clear the 3:1 threshold at 10.7, 8.1, 4.8 and 3.1, while the fifth manages 1.7 and is restricted to filled areas, never lines or points.

The palette is limited to five series colours. nus_pal() raises an error rather than recycle a sixth colour, since two series drawn in the same colour cannot be told apart in the finished figure.

Figures are SVG rather than PNG, so plot text stays sharp at any zoom.

D.4 Citing it

If a citation is expected of you:

Mishra, S. (2026). An Introduction to R: working with epidemiological data, using Singapore’s 2020 COVID-19 record. Saw Swee Hock School of Public Health, National University of Singapore. https://cerm-nus.github.io/r-intro/

@book{mishra2026rintro,
  author    = {Mishra, Swapnil},
  title     = {An Introduction to {R}: Working with Epidemiological Data,
               Using {Singapore}'s 2020 {COVID-19} Record},
  year      = {2026},
  publisher = {Saw Swee Hock School of Public Health,
               National University of Singapore},
  address   = {Singapore},
  url       = {https://cerm-nus.github.io/r-intro/}
}

This is a living document and the date in the page header is the date of the last render, so include an access date if the version you read matters. If it matters a lot, cite the commit: every page has a “View source” link in the right margin that takes you to the exact revision.

For the data, cite the three original sources rather than this book. Appendix B has them formatted.

D.5 Telling me something is wrong

Reports of errors are welcome. An error in a textbook propagates into every assignment written from it, which makes it worth more attention than an error in most other places.

The fastest route is the “Report an issue” link in the right-hand margin of the page you are on. It opens a GitHub issue with the page already identified. If you can see the fix, “Edit this page” opens the source file directly and turns your correction into a pull request.

A report that lets me reproduce the problem contains four things: which page and section, the code you ran, the complete error or warning text pasted rather than described, and the output of sessioninfo::session_info(). The third is the one most often trimmed, and it carries most of the information: “It said something about an object not found” and “Error: object ‘daily_cases’ not found” are different amounts of information.

Reports that a passage is confusing are as welcome as reports that a number is wrong. If you read something several times and still had to guess at its meaning, the passage most likely needs rewriting, and that is useful to know.
